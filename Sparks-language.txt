SPARK LANGUAGE REFERENCE                                      SIM95
======================================================================

SPARK is the programming language built into this machine. Programs
are text files ending in .SPK. Write them in the SPARK application
(Start > Programs > SPARK), press F5 to run, Ctrl+Break to stop.
From the Terminal:  SPARK C:\SAMPLES\HELLO.SPK

Everything in this file can be tried straight away. The examples in
C:\SAMPLES all run. So are the applications in C:\PROGRAMS: Files,
Notes, Chat, Sketch, Mines, Settings, Help, Network, Tasks, Monitor,
the web server and the Files and Chat services are all SPARK programs
- open one in SPARK, change a line, save, and run your version.


1. SHAPE OF A PROGRAM
----------------------------------------------------------------------
A program is a list of VAR declarations and SUBs. Main runs first.

    ' Comments start with an apostrophe.
    VAR count AS Integer          ' a global: visible in every SUB

    SUB Main ()
        VAR name AS String        ' a local: visible only in Main
        name = "world"
        count = count + 1
        Print("Hello, " + name + " (" + Str(count) + ")")
    END SUB

There are no line numbers, no GOTO and no GOSUB. Code lives in SUBs
and FUNCTIONs. Statements end at the end of the line. Names are not
case sensitive (Count, COUNT and count are the same variable) but the
convention is to write keywords in capitals.

A program with no window and no socket is a script: Main runs, Print
writes to a console, and the program ends when Main returns.

A program that opens a window, listens on a socket, or starts a timer
stays alive after Main returns. It then does nothing until an EVENT
happens - a click, a message, a tick - and the SUB you attached to that
event runs. The program ends when its last window closes, or when it
calls SYS.Exit(0).

Handlers run one at a time, each to completion. A handler that never
returns hangs only its own program: the rest of the machine keeps
working, the program shows as "Not responding" in Tasks, and End Task
kills it.


2. DECLARATIONS AND TYPES
----------------------------------------------------------------------
    VAR name AS Type              declares a variable (required before use)
    VAR n AS Integer = 5          with an initial value
    CONST LIMIT = 100             a named constant

Types:
    Integer       whole numbers          42, -7
    Real          decimals               3.14, 2.5e3
    String        text in double quotes  "hello", "say ""hi"""  ("" is a quote)
    Bool          TRUE or FALSE
    Array OF T    a list of T            VAR names AS Array OF String
    Handler       the name of a SUB, used for events
    GUI_*, NET_*  the classes listed in sections 8 and 9

Variables start as 0, "", FALSE, an empty array, or NOTHING (for
objects). Integer and Real convert to each other automatically
(Real to Integer truncates). Strings do not convert: use Str(n) to
turn a number into text and Val(s) to turn text into a number.
    Print("Total: " + Str(total))     ' right
    Print("Total: " + total)          ' compile error

Arrays grow with Add and are indexed from 0:
    VAR list AS Array OF String
    list.Add("one")
    list = ["a", "b", "c"]            ' array literal
    Print(list[0], list.Count)


3. SUBROUTINES AND FUNCTIONS
----------------------------------------------------------------------
    SUB Greet (who AS String, times AS Integer)
        VAR i AS Integer
        FOR i = 1 TO times
            Print("Hello " + who)
        NEXT
    END SUB

    FUNCTION Square (x AS Integer) AS Integer
        RETURN x * x
    END FUNCTION

Call them with Greet("Ann", 3) or Print(Square(7)). Numbers, strings
and Bools are passed by value; arrays and objects by reference.
Main takes no parameters; command-line arguments are in SYS.Args.
Every block ends with END; the block keyword after END is optional
but checked when present (END SUB, END IF, END WHILE, END SELECT,
END TRY, END FUNCTION). Loops end with NEXT.


4. CONTROL FLOW
----------------------------------------------------------------------
    IF x > 10 THEN
        ...
    ELSEIF x > 5 THEN
        ...
    ELSE
        ...
    END IF

    IF done THEN RETURN                      ' single-line IF

    WHILE NOT finished
        ...
    END WHILE

    FOR i = 1 TO 10 STEP 2                   ' i must be declared with VAR
        ...
    NEXT

    FOR EACH item IN list                    ' item must be declared with VAR
        ...
    NEXT

    SELECT CASE command
        CASE "quit", "exit"
            ...
        CASE "help"
            ...
        CASE ELSE
            ...
    END SELECT

    BREAK        leaves the innermost loop
    CONTINUE     jumps to the next iteration
    RETURN [v]   leaves the SUB (with a value in a FUNCTION)

Errors at run time (a missing file, an index past the end of an array,
division by zero) stop the program with a dialog unless you catch them:

    TRY
        text = FS.Read("C:\MYFILES\NOTES.TXT")
    CATCH err
        Print("Could not read the file: " + err)    ' err is a String
    END TRY

    THROW "something went wrong"       raises your own error


5. OPERATORS
----------------------------------------------------------------------
    +  -  *  /  MOD  ^        arithmetic (/ gives a Real; MOD is remainder)
    +                         joins two Strings
    =  <>  <  >  <=  >=       comparison (result is Bool)
    AND  OR  NOT              logic on Bools
    (  )                      grouping;  ^ binds tightest, then * / MOD, then + -


6. OBJECTS AND EVENTS
----------------------------------------------------------------------
    VAR win AS GUI_Window                declare
    win = GUI_Window.New("Title", 320, 200)   create with New
    win.Title = "Hi"                     set a property
    Print(win.Width)                     read a property
    win.Show()                           call a method
    win.onClose = Win_OnClose            attach an event handler

A handler is a SUB whose parameters match the event. The compiler
checks this and tells you when they do not:
    Handler 'Sock_OnMessage' expects (NET_Connection, String) but
    onConnect provides (NET_Connection) (line 22)

Controls belong to a window: GUI_Button.New(win). Position them with
SetBounds(x, y, width, height) in pixels from the top-left of the
window's client area. There is no layout engine and no form designer;
a SUB attached to win.onResize can move things when the window grows.

Several buttons can share one handler; the one that was pressed has
Focused = TRUE (see C:\SAMPLES\CALC.SPK).

Keyboard operation is free: Tab moves between controls, Enter presses
the button with Default = TRUE, Escape the one with Cancel = TRUE, and
"&Save" makes Alt+S press that button (the & marks the mnemonic).

NOTES ON NET_Socket
----------------------------------------------------------------------
A server:
    sock = NET_Socket.New()
    sock.onConnect = Sock_OnConnect
    sock.onMessage = Sock_OnMessage
    sock.Listen(80)

An inbound connection arrives PENDING. Your onConnect handler must
call conn.Accept() or conn.Reject(). If it returns without doing
either, the connection is dropped and a warning is printed to the
output pane. That is what a listening port is: a promise to answer.

A client:
    conn = sock.Connect("othermachine", 80)      ' waits until connected
    conn.Send("GET / HTTP/1.0")
Connect raises an error (catch it with TRY) when nobody answers:
"Connection refused" when the port is closed, "Connection timed out"
when the machine is not there, "Unknown host" when the name is unknown.

Messages are whole strings: one Send on one side is one onMessage on
the other. Voyager joins the messages it receives with line breaks
until the server closes, so a web server can Send its response line
by line and then Close.

Every machine has a Files service on port 139, a Chat service on
6667 and, when HTTPD.SPK is running, a web server on 80. Read
C:\DOCS\NETWORK.TXT for the protocols.


A COMPLETE NETWORKED, WINDOWED PROGRAM
----------------------------------------------------------------------
This web server logs each visit in a window and counts hits in its
title. Save it as C:\MYFILES\MYWEB.SPK, stop the shipped web server in
Settings (or change the port), run it, and open http://YOURNAME/ from
another machine's Voyager.

    VAR win AS GUI_Window
    VAR log AS GUI_ListBox
    VAR sock AS NET_Socket
    VAR hits AS Integer

    SUB Main ()
        win = GUI_Window.New("My Web Server", 360, 240)
        win.onClose = Win_OnClose
        log = GUI_ListBox.New(win)
        log.SetBounds(8, 8, 336, 196)
        sock = NET_Socket.New()
        sock.onConnect = Sock_OnConnect
        sock.onMessage = Sock_OnMessage
        sock.Listen(80)
        win.Status = "Listening on " + NET.LocalAddress + " port 80"
        win.Show()
    END SUB

    SUB Sock_OnConnect (conn AS NET_Connection)
        conn.Accept()
        log.Add(TIME.Clock + "  " + conn.FromAddress)
        hits = hits + 1
        win.Title = "My Web Server (" + Str(hits) + " hits)"
    END SUB

    SUB Sock_OnMessage (conn AS NET_Connection, message AS String)
        IF message.StartsWith("GET ") THEN
            conn.Send("HTTP/1.0 200 OK")
            conn.Send("Content-Type: text/html")
            conn.Send("")
            conn.Send("<html><body><h1>Hit number " + Str(hits) + "</h1></body></html>")
        END IF
        conn.Close()
    END SUB

    SUB Win_OnClose ()
        sock.Close()
        SYS.Exit(0)
    END SUB

11. PAGE SCRIPTS (SPARK inside a web page, run by Voyager)
----------------------------------------------------------------------
A web page can carry SPARK in a <script> tag. Voyager compiles it
when the page loads and runs it when the page says so. There is no
Main: HTML event attributes name the SUB to run, one rule everywhere.

    <body onload="Page_Load">            runs once, after the page is drawn
    <input type="button" value="Add" onclick="Add_Click">
    <input id="name" onenter="Add_Click">   Enter was pressed in the box
    <select id="size" onchange="Size_Change">
    <input type="checkbox" id="loud" onchange="Loud_Change">

    <script type="spark">
    SUB Page_Load ()
        PAGE.Status = "Ready"
    END SUB
    SUB Add_Click ()
        PAGE.Get("out").Text = "Hello, " + PAGE.Get("name").Value
    END SUB
    </script>

Every SUB an attribute names must exist and take no parameters;
Voyager reports a missing one in its status bar instead of running
the page. Elements are found by their id attribute with PAGE.Get(id).
Forms: <input> (text, password, checkbox, radio, button, submit, file),
<select>, <textarea> and <button> draw as the system's own controls.
A file box has a Browse... button that opens the Open dialog on this
disk; its Value is the chosen path.

A page script sees the page and nothing else. It has PAGE, TIME, MATH
and a SYS with only Ticks, Sleep and Beep: no FS, no NET, no windows,
no SYS.Run, no Input. Print writes to the status bar. A handler that
runs for too long is stopped. The sample C:\WEB\HELLO.HTM does all of
this; open it with File > Open Location and type file:C:\WEB\HELLO.HTM.

12. ACTIVE SPARK PAGES (SPARK on the server, run by HTTPD)
----------------------------------------------------------------------
A file in C:\WEB whose name ends in .ASP is run by the web server
instead of being sent. It is HTML with SPARK in it:

    <%@ import file="SITE.SPK" %>       SUBs and globals from a SPARK file
    <!--#include file="MENU.INC"-->     another file pasted in, as text
    <% VAR n AS Integer                 statements, run top to bottom
       n = Val(REQUEST.Query("n")) %>   with the text around them
    <p>n squared is <%= n * n %></p>    <%= expr %> writes a value
    <% IF n > 10 THEN %>                blocks may span text...
    <p>That is a lot.</p>
    <% END IF %>                        ...which is written only when reached
    <script runat="server">             SUBs declared by the page itself
    FUNCTION Twice (x AS Integer) AS Integer
        RETURN x * 2
    END FUNCTION
    </script>

There is no Main: the page's own text and code are the program. An
imported file is ordinary SPARK; a Main in it is ignored. Errors are
reported with the file and line they came from, as a page. A page sees
REQUEST, RESPONSE and SERVER (below), and FS, NET, TIME and MATH like a
program, and a SYS with only Ticks, Sleep and Beep. No windows, no
sockets. It runs on the server's machine, with the server's disk.

Forms. A <form> with a Submit button sends its fields on the URL and
the page reads them with REQUEST.Query("name"). Give the form
method="post" and they travel in the body instead: REQUEST.Method is
"POST" and REQUEST.Form("name") reads them. An <input type="file"
name="f"> in a POST form sends the chosen file from the visitor's
disk: REQUEST.Form("f") is its text and REQUEST.Form("f.filename")
its name. A whole request must fit in one network message, so keep
uploads under about 60K.

Cookies. RESPONSE.SetCookie("user", name) asks Voyager to send
user=name back with every later request to this server, and
REQUEST.Cookie("user") reads it: that is how a page knows who is
signed in. Setting a cookie to "" forgets it. Voyager keeps them in
C:\SYSTEM\COOKIES.TXT, one per line. RESPONSE.Redirect after a POST
is the polite way to land the visitor on a page they can Reload.

HTTPD.SPK does this with one line: conn.Send(ASP.Render(file, message,
conn.FromAddress)). ASP.Render returns the whole response, headers and
all. The sample is C:\WEB\HELLO.ASP, with C:\WEB\SITE.SPK imported.
